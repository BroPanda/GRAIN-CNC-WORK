# FREZALVIV — задачник ЧПУ

Черга робіт фрезерування для рекламної компанії FREZALVIV. Веб-застосунок,
відкривається у будь-якому браузері (телефон, планшет, ПК), верстка адаптивна:
на телефоні — таб-бар знизу, на ПК — сайдбар.

## Запуск

```bash
npm install
npm run pg           # локальний Postgres (окремий термінал, працює до Ctrl+C)
npm run dev          # http://localhost:3000
```

`npm run pg` піднімає справжній Postgres у `data/pg` (без Docker) і сам
записує `DATABASE_URL` у `.env.local`. Схема таблиць і початкова команда
створюються при першому запиті. Файли задач локально лежать у
`data/uploads/<id-задачі>/`.

```bash
npm run seed         # демо-задачі для перегляду (перезаписує задачі, не команду)
npm run build        # продакшн-збірка
npm start            # запуск продакшн-версії
npm run e2e          # автотести в справжньому браузері (dev-сервер має бути запущений)
```

## Ролі і права

| Роль | Хто | Базово може |
|---|---|---|
| **Власник** | Світлана (директор) | усе, завжди — права не відключаються |
| **Моделювання** | Тарас | створювати й редагувати задачі, заливати файли, доопрацьовувати |
| **Фрезерування** | Володя | брати в роботу, закривати, заливати файли |

Нових людей додає власник у розділі **Команда** (`npm run reset-team` повертає
склад до цього стану). Там же вписується **номер телефону** — саме за ним
людина потім заходить (див. **Вхід через Telegram**).

Права вмикаються **кожному окремо** в розділі **Команда** (доступний власнику):
створювати задачі, редагувати задачі, міняти чергу, завантажувати файли,
брати в роботу, закривати задачі, керувати командою.

## Як працює черга (гібридна модель)

- Є один **спільний пул** — задачі без закріплення бачать усі фрезерувальники,
  бере той, хто вільний.
- Будь-яку задачу можна **закріпити** за конкретним оператором — тоді її бачить
  і бере тільки він (решта її навіть не бачить у списку).
- Порядок задає власник: **перетягуванням** (мишкою або пальцем) або кнопками
  ↑/↓ на картці. Порядок зберігається в базі одразу.
- «Терміново» і галочка «на початок черги» ставлять задачу на верх.
- Фрезерувальник **не мусить брати верхню**: якщо вона не на часі — просто
  прокручує нижче і бере іншу.

## Життєвий цикл задачі

```
                  ┌──────────────────────────────────────┐
                  │                                      │
   [створено] → У ЧЕРЗІ → В РОБОТІ → ВИКОНАНО → (перевідкрити)
                  ↑          │
                  │          ↓
                  └── НА ДООПРАЦЮВАННІ ←── обов'язкова причина
                        (править моделювання/власник,
                         потім «Повернути в чергу»)
```

- **Взяти в роботу** — фрезерувальник; задача на доопрацюванні для взяття
  заблокована, поки її не повернуть у чергу.
- **На доопрацювання** — обов'язковий коментар-причина. Власник і відділ
  моделювання одразу отримують сповіщення з текстом причини.
- **Виконано** — з необов'язковим коментарем.
- **Скасувати / Перевідкрити** — для тих, хто має право редагування.

## Сповіщення

Дзвіночок із лічильником непрочитаних (у сайдбарі та в таб-барі) і сторінка
**Сповіщення** зі стрічкою подій — без нав'язливих алертів. Повна історія
кожної задачі (хто взяв, хто повернув, які файли додав, усі коментарі) видна
на сторінці задачі.

## Файли задачі

- **З переглядом у браузері:** STL, OBJ, 3MF, GLB, GLTF, PLY — модель
  крутиться пальцем, знизу показані габарити `X × Y × Z` мм і кількість
  трикутників. Орієнтація приведена до «Z вгору», як у CAD.
- **На завантаження:** STEP/STP, IGES, DXF, DWG, AI, CDR, EPS, SVG, PDF,
  G-code (NC/GCODE/TAP), архіви, таблиці.
- **Фото:** JPG, PNG, WEBP, HEIC — сітка прев'ю + перегляд на весь екран.
- До 60 МБ на файл. Файли віддаються через `/api/files/[id]` з перевіркою
  доступу: чужу закріплену задачу і її файли сторонній оператор не відкриє.

## Вхід через Telegram

Вхід прив'язаний до **номера телефону**, який власник вписує заздалегідь:

1. Власник у розділі **Команда** додає людину: імʼя, номер у форматі
   `+380671234567` і роль.
2. Людина відкриває бота FREZALVIV у Telegram і тисне «Поділитися номером».
   Номер підставляє сам Telegram зі свого акаунта — вписати чужий не можна.
3. Якщо номер є в команді — бот присилає посилання для входу (діє 15 хвилин
   і спрацьовує один раз). Якщо немає — відмова.

Номер можна писати як завгодно (`067…`, `+38 (067)…`) — він зводиться до
одного вигляду. Один номер = одна людина. Коли власник міняє людині номер,
стара прив'язка до Telegram скидається.

### Підключення бота

> ⚠️ **Спершу номери, потім бот.** Зайдіть у **Команду** і впишіть номер
> кожному — насамперед собі. Якщо ввімкнути бота, коли номерів немає, не
> зайде ніхто, включно з власником. У списку команди така людина позначена
> «номер не вказано — вхід неможливий».

1. У [@BotFather](https://t.me/BotFather) — `/newbot`, отримати токен.
2. Додати змінні оточення (локально в `.env.local`, на Vercel — у Settings →
   Environment Variables):

| Змінна | Що це |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від @BotFather |
| `TELEGRAM_BOT_USERNAME` | імʼя бота без `@` — для кнопки на `/login` |
| `TELEGRAM_WEBHOOK_SECRET` | свій випадковий рядок; ним відсікаються чужі запити |
| `AUTH_SECRET` | свій випадковий рядок для підпису сесії |
| `APP_URL` | адреса сайту; на Vercel підставиться сама |

3. Зареєструвати вебхук (Telegram приймає лише `https`, тому з робочої адреси
   сайту, не з localhost):

```bash
npm run telegram -- https://ваш-сайт.vercel.app
```

Скрипт сам пропише вебхук, опис бота і команду `/start`, а наприкінці
покаже, чи все зійшлося.

> **Поки бота не підключено** (немає `TELEGRAM_BOT_TOKEN`) на `/login`
> лишається тестовий вхід списком співробітників — саме так працює локальна
> розробка і автотести. Щойно токен зʼявився, цей шлях закривається сам.

Сесія лежить у підписаній cookie, тому підставити чужий id у браузері не
вийде. Після ввімкнення підпису всі старі сесії стають недійсними — усім
треба зайти заново (один раз).

## Публікація в інтернеті (Vercel)

Локально й у хмарі працює **той самий код**: різниця лише в двох змінних
оточення. Локально — вбудований Postgres і файли на диску, у хмарі —
Neon Postgres і Vercel Blob.

| Змінна | Локально | На Vercel |
|---|---|---|
| `DATABASE_URL` | пише `npm run pg` | з інтеграції Neon (Storage → Postgres) |
| `BLOB_READ_WRITE_TOKEN` | не задана — файли на диск | з інтеграції Blob (Storage → Blob) |
| `TELEGRAM_*`, `AUTH_SECRET` | не задані — вхід списком | вхід через бота (див. вище) |

Порядок:

1. Залити репозиторій на GitHub і додати проєкт на [vercel.com](https://vercel.com)
   (Next.js визначиться сам, нічого не налаштовуючи).
2. У **Storage** проєкту створити **Postgres (Neon)** і **Blob** — Vercel сам
   додасть `DATABASE_URL` і `BLOB_READ_WRITE_TOKEN` у змінні оточення.
3. Deploy. Таблиці й початкова команда створяться при першому відкритті
   сайту — жодних міграцій вручну.

Далі сайт відкривається за посиланням `*.vercel.app` з будь-якого телефона.
Перед тим як давати посилання стороннім, підключіть бота (див. розділ
**Вхід через Telegram**) — без нього на `/login` можна зайти будь-ким зі
списку.
